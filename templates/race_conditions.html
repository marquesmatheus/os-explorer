Race Conditions & Seções Críticas

Race condition é como dois cozinheiros tentando usar a mesma faca ao mesmo tempo — o resultado depende de quem pega primeiro.

Simulação Interativa

Duas threads incrementam um contador compartilhado (conta = 0). Execute sem lock (race condition) ou com lock (seguro).

As 4 Condições para Seção Crítica

Mutual Exclusion

Exclusão Mútua

Só um por vez. Se um cozinheiro está usando a faca, o outro espera. Nenhum dois processos podem estar na seção crítica ao mesmo tempo.

Progress

Progresso

Quem decide é quem está esperando. Se nenhum está na seção crítica e alguém quer entrar, essa pessoa decide quem entra. O processo que saiu não pode impedir.

Bounded Waiting

Espera Limitada

Ninguém espera para sempre. Existe um limite de quantas vezes alguém pode ser preterido. Nenhum processo fica em starvacao.

No Assumptions

Sem Suposições

Nenhuma suposição sobre velocidade. O algoritmo funciona independente de quanto rápido cada processador executa. Sem data races.

Algoritmo de Peterson

Resolução de exclusão mútua para dois processos. Usa apenas variáveis compartilhadas (sem hardware especial).

// Variáveis compartilhadas
int turn;           // Whose turn it is
bool flag[2];       // Want to enter

// Processo i (j = 1 - i)
void enter_cs(int i) {
    int j = 1 - i;
    flag[i] = true;     // "Quero entrar"
    turn = j;           // "Pode ir você"
    while (flag[j] && turn == j)
        ;               // Espera ativa
}

void exit_cs(int i) {
    flag[i] = false;    // "Já saí"
}

Em peterson.c, as compilações com -O2 podem reordenar as instruções! Use volatile ou barriers para evitar.

Resolução via Hardware

TestAndSet

// Instrução atômica (hardware)
bool test_and_set(bool *lock) {
    bool old = *lock;
    *lock = true;
    return old;  // Retorna valor ANTES
}

// Uso:
while (test_and_set(&mutex))
    ;  // Espera
// Seção crítica
mutex = false;

Swap

// Instrução atômica (hardware)
void swap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}

// Uso:
bool key = true;
while (key != false)
    swap(&lock, &key);
// Seção crítica
lock = false;

Locks no Mundo Real

Kernel Linux

Spinlocks e Mutexes

O kernel protege suas estruturas internas com spinlocks (curta espera, sem troca de contexto) e mutexes (longa espera, dorme).

Banco de Dados

Row Locks

A cada transação, o SGBD aplica locks de linha para garantir isolamento. O PostgreSQL usa MVCC para evitar bloqueios na leitura.

Containers

Docker & Kubernetes

Docker usa locks de arquivo para não corromper imagens. Kubernetes usa etcd com locks distribuídos para liderança de clusters.

Explorando com Ferramentas

# Ver futex (locks do userspace) de um processo
strace -f -e futex ./meu_programa

# Cada futex é uma seção crítica sendo protegida
# Saída típica:
futex(0x7ffd1234, FUTEX_WAIT_PRIVATE, 0, NULL) = 0   # Bloqueado
futex(0x7ffd1234, FUTEX_WAKE_PRIVATE, 1, NULL)  = 1   # Desbloqueado

# Detectar deadlocks com.strace
strace -f -e futex -p <PID> 2>&1 | grep FUTEX_WAIT

# Valgrind para detectar data races
valgrind --tool=helgrind ./meu_programa
